# Contributing

Contributions that make the template easier, safer, more accessible, or more useful are welcome.

## Good contribution areas

- accessibility improvements
- browser compatibility
- clearer beginner documentation
- bug fixes
- performance improvements
- new optional themes
- better CMS editing experience
- security improvements
- small reusable features

## Before changing code

Please keep the project's main goal in mind:

> A personal website that nontechnical people can manage after initial setup.

Avoid adding unnecessary build systems or dependencies unless they solve a meaningful problem.

## Suggested workflow

1. Fork the repository.
2. Create a descriptive branch.
3. Make the change.
4. Test locally.
5. Check the public pages.
6. Check JSON loading.
7. Check the CMS configuration if it was changed.
8. Open a pull request explaining the problem and solution.

## Code style

- Prefer clear vanilla JavaScript.
- Keep HTML semantic.
- Keep CSS understandable without special tooling.
- Comment configuration decisions that may confuse future contributors.
- Preserve backwards compatibility with existing content when practical.

## Documentation

If a change affects setup or editing behavior, update the corresponding documentation in `docs/`.
